# 寫場次筆記的規格（給協作的 agent）

專案：`/Users/matt/Claude/程式應用/ccc-2026-notes`，「2026 台灣社區整合照顧研討會」（台灣社會福利總盟主辦，11/14–15）的學習網站。
讀者是長照、社福、醫療的實務工作者，想快速掌握：政府未來政策方向，以及各單位可以學習仿效的做法。

## 輸入
- 逐字稿：`raw/<videoId>.txt`，每行 `[h:mm:ss] 文字`。Day 1 = `a68KpkrjF9A`，Day 2 = `PiKwuQceCC0`。
  這是 Whisper 語音辨識結果，有同音錯字（人名、機構、術語常錯）。請依上下文和講義判斷正確意思，不要照抄錯字。
- 議程：`notes/sessions.json`（場次 id、講者、單位、講義 Drive id）。
- 講義文字：`raw/handouts_txt/<講義 Drive id>.txt`（PDF 抽出的文字，有些是圖片版所以很少字）。用來核對人名、數字、計畫名稱。
- 讀檔請用 Read 搭配 offset/limit 或 `sed -n`、`grep -n`，只讀你負責的時間範圍。

## 輸出：每個場次一個 `notes/<場次id>.json`
```json
{
  "t": 2520,
  "summary": "120–220 字的繁體中文摘要：這場在講什麼、主要主張、最重要的結論。",
  "points": [
    {"t": 2710, "kind": "政策", "tags": ["健保給付", "在宅急症照護"], "text": "一句到三句的重點，具體寫出計畫名稱、對象、數字、時程。"}
  ]
}
```
- `t`：場次實際開始秒數（主持人介紹此講者、或講者開口的那一行；不是議程表上的時間）。時間戳 `[h:mm:ss]` 換成秒數。
- `points[].t`：該重點在影片中出現的秒數，取最接近的那一行時間戳（可以略早幾秒），讓使用者點了就能聽到原話。
- `kind` 只能用：`政策`（政府已推動／將推動的政策、計畫、給付、法規、時程）、`策略`（單位實際做法、模式、流程、可仿效的經驗）、`數據`（具體數字、成效、統計）、`挑戰`（困境、缺口、痛點）、`建議`（對政府或制度的建議、呼籲）。
- `tags` 1–3 個，只能從這張表選（第一個 tag 用最主要的主題，政策方向頁用第一個 tag 分組）：
  健康台灣、長照3.0、醫照整合、居家醫療、在宅急症照護、急性後期照護、復健病房、出院準備、社區醫療、住宿式機構、健保給付、重症兒童、就學與教育、偏鄉、失智照護、安寧緩和、人力培育、數位科技、家庭照顧者、日本經驗、財源與預算、跨部會協作
- 每場演講 10–25 則重點（主講／專題演講可到 30 則）；開幕、主持引言 2–6 則；綜合座談 8–20 則（寫出提問者單位、問題與回應者的答覆重點，誰說的要寫明，例如「石部長回應：…」）。
- 文字用台灣繁體中文、台灣用語，改寫整理，不要大段照抄逐字稿。不確定的數字或名稱寧可不寫，或寫「約」。不要編造逐字稿裡沒有的內容。
- 寫完後用 `python3 -c "import json;json.load(open('notes/<id>.json'))"` 確認 JSON 合法。
